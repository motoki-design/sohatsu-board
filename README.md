# sohatsu-board — 事業創発室 案件ダッシュボード

石田・勝部・竹下・守山（室長）の案件を、室の定例と全社向けに一覧する。
**合言葉を入れないと中身が見えない**（ページに埋まっているのは暗号文だけ）。

- 公開URL: https://motoki-design.github.io/sohatsu-board/

## 区分の並び（2026-09-07 に逆転した）

```
仕組みづくり → 技術向上 → 協業検討 → 企画・プロポ → 新規事業 → 進行業務
```

出典＝2026-09-07 事業創発室 週次定例。守山さん「最初に進行業務を上げてしまった。
**いちばん大事なのは一番下の『仕組みづくり』なので、逆転させる**」。

室は組織最適化に半分のエフォートを置く、という主張を並び順で示している。
**開いた人が最初に見るものが、室が何を大事にしているかの宣言になる。**
中4つ（技術向上・協業検討・企画・プロポ・新規事業）の相対順は逆転の結果で、
個別に決めたものではない。並びは `template.html` の `TYPE_ORDER` 1行で変えられる。

## データの持ち方

| 層 | 置き場 | 更新 |
|---|---|---|
| **案件** | 事業創発室 案件マスタ（GSheet） | `node refresh.js` → `node build.js` → push |

**平文データ（`payload.json`）はこのリポジトリに置かない。** 置き場は `config.local.json`（gitignore済み）で渡す。

## 更新の手順

```
node refresh.js                          # 案件マスタを読んで payload.json を更新
SOHATSU_PASS='合言葉' node build.js       # 暗号化して index.html を生成
git add index.html && git commit -m "更新" && git push
```

平日18:30の `GanttDailySync`（会社PC）が上の3行を1日1回流す。
**定例の直前に最新にしたいときは手で流す。**

## ★2026-09-07 の改修と、失われたもの

**それまでは、このリポジトリの `index.html` に案件マスタのシートIDが平文で入っていた**
（`案件マスタを開く ↗` のリンクと `const SHEET = "…"`）。そのシートは
「リンクを知っている全員が閲覧可」だったので、**公開URLを見た人が主担当・次アクション・
関与メンバー・直近の動きまで読める状態だった**（匿名で gviz を叩いて取得できることを実測）。

そこで **refresh.js がサーバ側で読み、build.js が payload をまるごと暗号化する**形に移した。

**引き換えに「マスタを直す→ページの ↻ で即反映」が失われた。** サーバ側取得にする以上、
避けられない。1日1回のバッチと、定例直前の手動更新で補う。
`↻ 更新` ボタンは残すと壊れて見えるので、**「マスタ取得 ◯時点」の表示に置き換えた**。

### 履歴について

**シートIDはこのリポジトリの公開履歴に残っている**（2026-07 の初回公開分・10箇所）。
いまのファイルから消しても、GitHub の履歴からは消えない。
ただし**履歴に入っているのはIDとコードだけで、案件の中身は入っていない**
（データは常に実行時にシートから取っていたため）。
**IDだけでは何も読めない**ので、実際に閉じるのは**マスタの共有設定の変更**（守山さん）である。

## 環境変数

| 変数 | 用途 |
|---|---|
| `SOHATSU_PASS` | 合言葉（`build.js`） |
| `SOHATSU_SA` | サービスアカウント鍵のパス（`refresh.js`） |
| `SOHATSU_PAYLOAD` | `payload.json` のパス |
| `SOHATSU_MASTER_SHEET_ID` | 案件マスタのID（`refresh.js`） |

**いずれも値はリポジトリに書かない。** 各端末の `config.local.json` か環境変数で渡す。

## 暗号の仕様

PBKDF2-SHA256（250,000回）で合言葉から鍵を導出し、AES-256-GCM で `payload.json` を暗号化。
ブラウザ側は WebCrypto で復号する。ライブラリは使っていない。
一度開くと `sessionStorage` に合言葉を持つのでリロードしても再入力は要らない。タブを閉じれば消える。
**toku-board と同じ実装**（`build.js`・`lib/gsheet.js` はあちらから持ってきた。同じ問題に2つ目の解を作らない）。

## 既知の注意

- マスタの列名（`種別／案件番号／業務名／主担当／工期／備考／関連リンク／関与メンバー／状態／次アクション／期限／直近の動き／更新日`）を見出し名でマッピングしている。**必須列が消えていると `refresh.js` が止まる**（黙って空のページを出さない）。
- `refresh.js` が失敗したときは payload の前回値が残る。ページの「マスタ取得 ◯時点」が古いままになるので、そこで気づける。
- 健康・人事等の機微情報はマスタにもこのページにも入れない。
- Node 22 の標準機能だけで動く（外部パッケージなし）。
